# imabubakr.github.io

Personal site of Muhammad Abu Bakar (Geospatial Data Specialist, Freiburg).
One page per language: English at `/` (`index.html`), German at `/de/` (`de/index.html`).

## Deploy and run

- GitHub Pages, classic mode: the root of `main` is published as-is (`.nojekyll`, no build step).
  Pushing to `main` puts changes live at https://imabubakr.github.io/.
- Local preview: `python3 -m http.server 8000` in the repo root, then open `localhost:8000/` and `localhost:8000/de/`.
  It sends no `Cache-Control`, so browsers may run stale JS/CSS: hard-reload. CSS/JS links carry `?v=YYYYMMDDx`;
  bump it in `index.html`, `de/index.html` (and `404.html` for CSS) whenever those files change.
- Old URLs are redirect stubs and must keep working: `about.html` → `/#about`; `resume.html`, `contact.html`,
  `projects.html` → `/#cv`; `geo.html` → `/`. Keep section ids (`about`, `cv`, `contact`) stable; both languages share them.

## Files

- `assets/css/site.css`: all styles. Tokens at the top; sections marked with `/* --- name -- */` banners.
- `assets/js/site.js`: theme toggle, nav highlight, language switch keeps the current `#section`, plates viewer,
  "save cv as pdf" button.
- `assets/js/hero-map.js`: hero map tools (live coordinates/elevation, two-point elevation profile).
- `assets/topo/hero-contours.{svg,json}` and `hero-contours-dem.bin`: generated. Don't edit by hand.
- `assets/plates/`: generated by `tools/plates/build_plates.py` (thumbnails, large images, WebM/MP4 for animations).
- `assets/img/`: portrait (WebP, 200/400 px) and `og.png` (social preview).
- Repo-root images (`*.png`, `*.jpg`, `*.gif`…) are the old site's gallery and the plate sources. Which ones to
  keep or remove is still to be decided with the user. Don't delete them on your own.

## Hero map pipeline

1. `cd tools/contours && npm ci` (once). Needs GDAL ≥ 3.6 with Python bindings and numpy.
2. `tools/contours/make_contours.sh` downloads Copernicus GLO-30 around 47.997791 N, 7.842609 E, reprojects to
   WGS 84 / UTM 32N, smooths, runs `gdal_contour` (10 m, every 5th = index), simplifies with mapshaper, places
   uphill-facing labels, runs SVGO. See `--help` for options (`--dem` for a local DEM).
3. `python3 tools/contours/build_hero.py index.html de/index.html` injects the map, graticule ticks, coordinates and
   footer values between the `<!-- build:name -->` markers, formatted per `<html lang>`.
   `make_contours.sh` also writes the 50 m elevation grid and the map→lat/lon formula used by `hero-map.js`.
   Region map for the fullscreen viewer (Kaiserstuhl to Feldberg, 40 x 36 km, CI 20 m, 100 m grid): run the
   region command from `make_contours.sh --help` (own `--work` folder!), then
   `python3 tools/contours/region_extras.py` (summit labels found as DEM maxima, hero frame and marker).
4. If the hero changed visibly, regenerate `assets/img/og.png` with `tools/og/make_og.mjs` (instructions in the file).

## Plates (Visualizations section) and certificates

Edit the `PLATES` or `CERTS` list (source file, EN/DE short title and caption) in `tools/plates/build_plates.py`, then run
`python3 tools/plates/build_plates.py` (needs Pillow and ffmpeg; `--skip-media` to only rewrite the markup).
It writes the media to `assets/plates/` and the grids into both pages between `<!-- build:plates -->` /
`<!-- build:certs -->` markers. The viewer pages through one grid at a time.

## Page background

`python3 tools/layers/build_layers.py` writes `assets/layers/village.svg`: building **outlines only** (no fill) of the
village Ebringen near Freiburg from OpenStreetMap (cached in `tools/layers/work/`; change `VILLAGE` to use another
place). It's one continuous background fixed behind everything below the hero (`body::before`), painted with
`--contour` through a mask, faded towards the centre so text sits on calm paper, loaded after page load. No bands or
per-section layers: the user found those looked broken. Credit "© OpenStreetMap contributors" stays in the footer.

## Design rules

The look is "technical survey sheet", deliberately toned down: the cartographic character lives in the hero map,
the mono labels and the scale bar. Everything else is quiet. The user prefers calm and centred over decorative.

### Palette (CSS custom properties; never hard-code colours)

| Token | Light | Dark | Use |
|---|---|---|---|
| `--paper` | `#e9eae6` | `#0e1215` | background |
| `--ink` | `#141719` | `#e4e6e7` | text, work markers |
| `--muted` | `#4e5358` | `#8d979e` | secondary text, dates, labels |
| `--contour` | `#8a6a4a` | `#6c7f8c` | contour lines, education markers |
| `--grid` | `#c9cbc5` | `#232c33` | hairlines (nav, strip, footer), graticule |
| `--accent` | `#b8380c` | `#ff6a2b` | links and accent **text** |
| `--accent-mark` | `#d2410f` | `#ff6a2b` | non-text: location marker, current-job marker, focus ring |
| `--lc-*` | muted map tints | dark tints | land cover in the orbit-to-drone map only |

- Light `--accent` is darkened from the spec's `#D2410F` (3.9:1) to `#B8380C` (4.8:1) for WCAG AA text contrast.
- Accent is used sparingly: location/"you are here" markers, links, focus. Nothing else.
- Dark mode: `prefers-color-scheme`, overridden by `html[data-theme]` from the toggle (stored in `localStorage.theme`).
  Any new token must be defined in all three places (`:root`, the media query, `[data-theme="dark"]`).

### Typography

- IBM Plex Sans (text, headings) and IBM Plex Mono (numbers, dates, coordinates, labels, metadata).
  Self-hosted latin-subset woff2 in `assets/fonts/`. **Only weights 400 and 500.** No other fonts.
- Hero `h1`: the owner's sentence "Hello, I'm Bakar, a geospatial data professional with a passion for all things
  spatial." (DE: "Hallo, ich bin Bakar, …"), 500, moderate size (max 2.5rem), bottom-left. No big title, no red
  coordinates line (owner's wish).
- Running text is 15px (0.9375rem) everywhere, one size per text block (no bigger "lead" paragraphs); the owner
  found the earlier scale too big.
- Section titles: Plex Sans 500, `clamp(1.625rem, …, 2.375rem)`, `letter-spacing: -0.035em`. No `[0n]` numbers above
  them or in the nav (owner removed them, 2026-10-09).
- Mono is for metadata only: never for running text.
- Centre only short text (headings, one-liners, at most about 3 lines; use `text-wrap: balance`). Longer text is
  left-aligned, even inside centred columns.

### Layout

- No page frame, no boxes, no cards, no rounded corners, no shadows, no gradients. The only lines are `--grid`
  hairlines (under the nav, under the hero strip, above the footer) and the timeline line. Don't add more.
- Mobile first; the content column is max 860 px. Every section opens the same way on the page's centre axis:
  `header.section-head` → `h2.section-title` + optional one-line `.section-sub`.
- Order of the page: hero (who) → About (story + timeline) → From orbit to drone (career story) → CV (details) →
  Visualizations (work samples) → Contact (action) → footer collar.
- Nav: a modern bar in Plex Sans: name left, `About  Orbit  CV  Visuals  Contact` centred (DE: Über mich, Orbit,
  Lebenslauf, Grafiken, Kontakt), `EN DE | ☀ Light ☾ Dark` right (DE `Hell`/`Dunkel`; `.theme-switch`, two buttons; icons only on phones).
  Language and theme options are styled like the section links (same type, muted, active = ink + accent bar). Translucent paper with backdrop blur;
  links muted, the current one ink with a 2px `--accent-mark` bar on the nav's bottom edge. Phones: two rows (name +
  tools, then the links). `--nav-h` is 84px on phones, 57px from 900px. The hero strip says `SHEET 01 / 05`
  (`BLATT` in German). Update it if sections are added.
- Hero: real contours (hero only, faint), graticule meridians, top strip with sheet number, longitude ticks and
  `EPSG:4326`. "FREIBURG IM BREISGAU" as a map label (ink dot + spaced caps) at the Münster's true position
  (`build:hero-place`, written by build_hero.py); on phones the name sits left of the dot.
- About timeline: a centre
  line that starts at the first phase label (not at the photo); `EDUCATION`/`CAREER` labels sit on the line;
  entries alternate sides (`.tl-l`/`.tl-r`) with diamond markers and short connectors; the current job is
  `.tl-now` (accent). On phones entries stack on the centre line.
- Beagle Systems (current employer, Hamburg) is linked to https://beaglesystems.com/ in About and the CV, with a
  one-line description under the job taken from their site. Keep it factual.
- Certificates: a `<details>` (`#certificates`) at the end of the CV, closed by default ("show all 6"), opened by the
  "View certificates" link or the `#certificates` hash; hidden in print.
- About: a **short** introduction in two paragraphs (owner's wish, 2026-10-09): background + earlier work
  (satellite data, MapTransfer, Karuna), then what the current Beagle job involves. No job pitch (the owner is not
  job-hunting). Text → timeline → portrait below the timeline (owner's choice, 2026-10-09).
- Portrait: the **uncropped** square selfie `me.jpg` → `assets/img/portrait-{320,640}.webp` (owner disliked the
  crop). Shown as a duotone in map colours (`.duotone`, `--photo-shadow` / `--photo-light` per theme) with soft
  only the outer ~9% of the edges faded into the paper by a CSS mask (`.portrait`); the owner wants the photo
  clearly visible, not washed out. The print header uses it too.
- CV: German Lebenslauf layout, kept **short and tight**: date column (mono, `MM/YYYY`) + entry; role and
  employer on one line (`.cv-org`); reverse chronological; key-value rows for skills and languages. No rules
  between rows. Projects belong in the CV (under the job or "Academic projects"), not in a separate section.
- Hero map tools (`assets/js/hero-map.js`, one engine for hero and fullscreen viewer): hovering shows lat/lon +
  elevation in the strip (replacing `EPSG:4326`); two clicks/taps draw an accent survey line and open the elevation
  profile panel (paper background, no border). Never block page scrolling on touch in the hero (no drag gestures).
- Two map views, switch "contours | ridges" bottom-right of the hero (synced with the viewer): ridge lines are drawn
  in JS from the 50 m grid (rows every 100 m, 50 m when zoomed in; 2.5× vertical exaggeration, stated in the viewer;
  paper fill so nearer ridges hide farther ones). In ridge view the cursor snaps to the visible ridge line and the
  profile line drapes over the ridges.
- "fullscreen" loads the region map (`assets/topo/region-contours.*`, ~410 KB, only on open) and starts on the
  hero's frame (dashed in contour view); ⤢ shows the whole region with summit labels. Ridge exaggeration is per
  map (hero 2.5×, region 4×) and the viewer states the value in use. `dialog.map-viewer`: zoom (−/+/reset, wheel, pinch, +/- keys), pan (drag, arrow keys), live
  readout, profile, scale bar. The viewBox follows the stage's aspect (no letterboxing; portrait screens fill the
  height). Labels stay ~10 px at any zoom. Esc clears a profile first, then closes.
- Visualizations: still thumbnails (4:3, `object-fit: cover`) in a 2/3-column grid with mono `PLATE 0n` /
  `TAFEL 0n`; nothing moves on the page. Clicking opens `dialog.lightbox`; animations play only there (not under
  reduced motion).
- Print: printing or "save cv as pdf" gives a two-page A4 CV (print header with photo + CV only, always light).
  Check it after CV changes (two pages).
- 404: "Off the map." on Null Island (0.0000°N 0.0000°E).
- Footer collar: scale bar (1 km at the hero map's on-screen scale), `WGS 84 / UTM 32N · CI 10 m`, legal lines,
  DEM credit.
- Motion: smooth scrolling (only without `prefers-reduced-motion`) and subtle hovers. Nothing else.

### Content and languages

- Never invent facts (dates, tools, numbers, sensors). Ask the user and list open questions instead.
- Every content change goes into **both** `index.html` and `de/index.html`.
- German: correct German CV conventions ("seit 11/2025", Berufserfahrung, Ausbildung, Kenntnisse,
  Sprachkenntnisse), decimal commas, `O` for east, formal "Sie". Keep official English job titles, degree,
  course and thesis names (thesis titles in „…“), marked `lang="en"`. No `hyphens: auto` (browsers split German
  compounds badly); use `&shy;` in long headings.
- US English spelling on the English page (matches the original CV).
- Professional register: **no contractions** on either page ("I am", "do not", never "I'm", "you'd").
- About text positions the owner as working at the intersection of Earth observation, data engineering (pipelines)
  and AI (fine-tuning detection models, open-source large models and VLMs, edge deployment), with the geology /
  satellite background after that. Keep it factual: only things stated in the CV or by the owner.

### Accessibility and performance

- Semantic landmarks, one `h1`, skip link, visible `:focus-visible` outline, touch targets ≥ 24 px,
  decorative SVG `aria-hidden`, real `alt` text, WCAG AA contrast in both themes.
- No third-party requests (fonts, scripts, analytics). Images as WebP with `width`/`height`, `loading="lazy"` below the fold.
- Last Lighthouse run (2026-10): accessibility, best practices, SEO 100; performance 99–100 (EN and DE, mobile and desktop).
